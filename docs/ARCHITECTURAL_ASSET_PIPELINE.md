# Architectural asset pipeline — showcase villa neighbourhood

Branch `feature/architectural-asset-pipeline`. Milestone scope: ONE residential
tile representation (the Homes structure) rebuilt as authored GLB assets with
three eras. Town, sprawl, other structures, simulation and rules are unchanged.

## 1. Audit (before any code change)

State audited: `main` at `f80abdf` (horizontal urbanism merged). The live GitHub
Pages build (`index-B-SWmvLf.js`) is **older** — it predates horizontal urbanism.

**Why the villas look tiny and generic** — it is scale first, modelling second:

| Quantity | Value | Source |
|---|---|---|
| Tile | 0.06 m (6 cm); board 14 × 10 tiles = 0.84 × 0.60 m | `config/scenario.ts` |
| Villas per homes tile | 6, parcel pitch 18 mm | `world/villas.ts` |
| Villa footprint / storey | ≈ 7–11 mm / 5.5 mm | `villas.ts` |
| Window | 1.6 × 2.2 mm | `villas.ts` |
| Desktop camera | (0, 1.46, 0.46) → board ≈ 1.18 m away, 50° FOV | `iwsdk.config.json` |
| Desktop pixels per metre at the board (1280×800) | ≈ 730 px/m → **tile ≈ 44 px, villa ≈ 7 px, window ≈ 1 px** | computed, matches screenshots |
| Seated XR eye → board centre | ≈ 0.72 m | (0, 1.2, 0.08) → (0, 0.78, −0.5) |
| Quest 3 (≈ 25 px/deg) | **villa ≈ 20 px, window ≈ 3 px**; IWER capture ≈ half that | computed |
| Sun shadow map | 1024² over 1.2 × 1.2 m → **1.2 mm per texel** — coarser than the villa details, so shadows barely register | `world/ambient-system.ts` |
| Materials | untextured vertex colour (`PAINTED`), no AO, flat colour blocks | `world/palette.ts` |
| Geometry | axis-aligned boxes and 4-sided cones; no overhangs, recesses or roof pitch variety | `villas.ts` |

Consequences: at normal gameplay distance all detail below ~5 mm (windows,
shutters, PV strips, battery, chargers) is sub-pixel. What remains readable is
only silhouette, roof colour and the contrast between house, garden and street —
and those were weak (same-height boxes, low-contrast lawns, no contact shadow).
The desktop camera cannot simply move closer: the HUD and action panels already
frame the board left and right.

**Direction for the showcase**: readable silhouettes over micro-detail —
larger houses relative to their parcels (mild tabletop exaggeration), pitched
roofs with overhangs, strong wall / roof / garden / hedge contrast, baked ambient
occlusion and contact shadows, texture variation instead of flat colour, and a
tighter shadow frustum.

## 2. Asset pipeline

Blender **5.2.2 LTS** is installed (`/Applications/Blender.app`), so the
neighbourhood is generated by a reproducible Blender Python script — no
external models, textures or HDRIs, so there is nothing third-party to license.

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
  -P scripts/assets/build_villa_district.py -- public/models
node scripts/assets/inspect-glb.mjs public/models/villa-district.glb
```

What the script does (fixed seed, same output every run):

1. **Texture atlas** (512², 16 cells) painted procedurally with numpy: stucco,
   stone (ashlar courses), paving, terracotta roof tiles (overlapping rows),
   timber, soil/bark, gravel, lawn, foliage, green roof, canvas, PV modules
   (cell grid + frames), glass, asphalt, pool water. Plus a matching
   roughness atlas (PV, glass and water are glossy; plaster, roof and planting
   matte). Exported as JPEG inside the GLB.
2. **Geometry** from a small architectural vocabulary: volumes with plinths,
   hip and gable roofs with deep eaves and fascias, windows with shutters
   (2026) or larger glazing with timber brise-soleil (2035+), garden-side
   sliding doors, pergolas (open / canvas / vine), terraces, pools with
   coping, low front walls with gates, hedges or dry-stone walls, driveways,
   cars, olive / umbrella-pine / cypress trees, lavender beds, a street with
   sidewalks, street trees, cycle lane (2035+) and bioswale (2050).
3. **Baked ambient occlusion** per vertex corner by ray casting against the
   whole neighbourhood (28 cosine-weighted rays, 6 mm reach, strength 0.72;
   grounds are subdivided so houses and trees cast contact shadows). It is
   stored in the vertex colours (tint × AO), so it costs nothing at runtime.
4. **Export**: one GLB with three root nodes `era-0/1/2`, each ONE mesh with ONE
   single-sided material (atlas + roughness + vertex colours) → one draw call
   per visible district.

Runtime: `src/assets.ts` declares `villa-district` (critical preload);
`createVillaDistrict` in `src/world/villas.ts` clones the era nodes (shared
geometry and material); the procedural model remains as fallback and for A/B
review (`?procedural-villas`). Time travel still switches `era-N`, the Plan
A/B dioramas keep the textured material (`mini-board.ts`).

## 4. Presentation changes

- **Desktop framing** (`iwsdk.config.json`): camera (0, 1.46, 0.46) → (0, 1.30, 0.34),
  look-at (0, 0.70, −0.50). The board grows ≈ 1.27× on screen (tile-centre spread
  713 → 904 px at 1280 × 800). Chosen by a search over camera poses that keeps every
  non-water, non-protected tile clear of the HUD, action and time panels (a closer
  pose, 1.44×, put two buildable plains under the HUD and was rejected). XR is
  unaffected (head pose drives the camera).
- **Shadows**: sun shadow map 1024² over 1.2 m → 2048² over 1.1 m (≈ 0.54 mm per
  texel instead of 1.2 mm), so eaves and trees cast readable shadows.
- Readability choices at tabletop scale: ~1.25× vertical exaggeration
  (3.7 mm storeys), 1 mm roof overhangs (the roof is what the gameplay camera
  sees), lighter hedges than the first pass, saturated terracotta, white plaster.

## 7. Performance and cost (desktop Chromium + IWER — not a Quest)

| Measure | Before | After |
|---|---|---|
| Asset | procedural (no download) | `villa-district.glb` **1,334 KB** (467 KB gzipped); atlas JPEG 43 KB + roughness 5 KB |
| Triangles per district (visible era) | ≈ 1.5–2.5 k | 4,042 / 5,048 / 5,678 (2026 / 2035 / 2050) |
| Draw calls per district | 1–2 | 1 (one mesh, one material per era) |
| Desktop close-up, 2 districts, 2026 — calls / tris | 71 / 25.3 k | 69 / 30.1 k |
| Desktop close-up, 2050 — calls / tris | 68 / 27.8 k | 66 / 33.9 k |
| IWER stereo seated, same plan — calls / tris | 236 / 86.2 k | 230 / 100.6 k (+17 % tris) |
| Production build size | 3.6 MB | 4.9 MB |
| Time to app ready, 10 Mbit/s + 40 ms RTT, cache off (3 runs) | 1.15–1.46 s | 2.17–2.47 s (`vite preview`, GLB served uncompressed) |
| Shadow map | 1024² | 2048² (4× shadow-map memory, ≈ 16 MB → see note) |

Frame time in this environment is software-rendered and noisy (IWER median
≈ 320–370 ms in both states) and says nothing about a Quest. Notes: a 2048²
depth shadow map is common on Quest-class hardware but costs fill rate; if it
proves heavy on device, revert to 1024² with the tighter frustum (still ≈ 1.1 mm
per texel → better than before). Draco would shrink the GLB further but its
decoder is fetched from a CDN by the IWSDK loader, so it was not used.

## 8. Known limitations and next steps (not done — awaiting visual approval)

- Only the Homes tile is authored. The town centre, sprawl, roads, parks, solar,
  wind and terrain are still procedural, so the district now looks more detailed
  than its neighbours.
- Every homes tile shows the same authored layout (placement rotation varies it).
  The pipeline can emit more layouts once this one is approved.
- 2050 integrated PV roofs dominate the colour from the gameplay camera (by design:
  the solar transition is the story), at the cost of some terracotta warmth.
- The desktop camera is closer (≈ 1.27×); XR framing is unchanged.
- Not tested on a physical Quest; all XR evidence is IWER.
